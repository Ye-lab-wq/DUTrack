# 端到端语言调制实验主线与工程实现指导

## 0. 当前阶段定位

当前工作不应继续沿着“手工筛词、手工分类、手工保留 anchor、手工压制 context”的方向堆规则。前面 Stage 1 / Stage 2 的实验已经说明：

```text
1. 直接使用 BLIP caption 替换语言，容易导致目标身份漂移。
2. 固定 anchor 可以稳定语言状态，但过于保守，不能解决语言描述随时间过时的问题。
3. Stage 2 reliability only 可以改善 word weight 与 target-hardneg gap 的对齐。
4. subject floor、context cap、soft type prior 都会破坏这种对齐。
5. 仅靠 runtime 调整词权重，暂时难以明显改变 IoU。
```

因此，当前新的主线应从：

```text
规则式词筛选 / 词分类 / floor-cap
```

转向：

```text
language-conditioned multi-query prior
```

也就是让语言状态生成一组可学习的 language queries，通过 cross-attention 或 compatibility scoring 定位 search tokens，再把结果作为 center-score prior 注入 tracker。

核心思想：

```text
语言不是被直接信任；
语言先生成定位 query；
query 必须在 search token 中形成可验证的目标/干扰区分；
最终只对 center score 做有界增量修正。
```

---

## 1. 总体实验主线

建议将后续实验分为四个阶段：

```text
Stage 1: Per-word visual evidence diagnosis
Stage 2: Soft word reliability diagnosis
Stage 3: Language-conditioned query prior
Stage 4: End-to-end training of query prior module
```

其中 Stage 1 / Stage 2 已经基本完成诊断，后续重点是 Stage 3 / Stage 4。

---

# Stage 1：词级视觉证据诊断

## 1.1 目标

验证每个语言 token 是否能在 search 区域中区分：

```text
目标区域 P
hard negative 区域 N
```

核心公式：

```text
R_i(j) = sim(word_i, search_token_j)

s_pos(i) = mean_{j in P} R_i(j)
s_neg(i) = mean_{j in N} R_i(j)

gap_i = s_pos(i) - s_neg(i)
```

解释：

```text
gap_i > 0: 该词更支持目标区域
gap_i = 0: 该词区分性弱
gap_i < 0: 该词更支持 hard negative 或背景
```

## 1.2 关键结论

Stage 1 的价值不是提升 IoU，而是回答：

```text
当前 word-visual compatibility 是否有真实判别性？
当前 word weight 是否等价于视觉判别性？
```

必须区分：

```text
word_weight 高：模型当前更依赖这个词
word_gap 高：这个词更能区分目标和 hard negative
```

如果 `word_rank_by_weight` 和 `word_rank_by_gap` 不一致，说明不能直接相信模型原始 word weights，需要用 target-hardneg gap 做 reliability 校准。

## 1.3 当前结论

Stage 1 结果显示：

```text
Biker / HOOT:
  oracle gap 和 deploy gap 都为正，可作为后续语言调制试验对象。

OLOD:
  deploy gap 接近 0 或为负，暂时不适合进行语言更新试验。
```

因此后续阶段先使用：

```text
OTB-Lang: Biker
HOOT: backpack-004
```

暂时不使用 OLOD 作为主判断序列。

# Stage 2：Soft Word Reliability 诊断

## 2.1 目标

固定 anchor language，不删除词、不改写句子，只为每个词维护一个运行时可靠性：

```text
reliability_i
```

它不是模型参数，不参与反向传播，只是跟踪过程中的状态变量。

## 2.2 核心公式

对每个词：

```text
gap_i(t) = mean_{j in P_pred} R_i(j) - mean_{j in N_hard} R_i(j)

e_i(t) = sigmoid(gap_i(t) / tau)

r_i(t) = momentum * r_i(t-1) + (1 - momentum) * e_i(t)
```

最终词权重：

```text
base_weight_i = softmax(word_logits_i)

final_word_weight_i =
base_weight_i * r_i(t)
----------------------
Σ_k base_weight_k * r_k(t)
```

最终：

```text
word_direct_score_j = Σ_i final_word_weight_i * R_i(j)
```

## 2.3 已完成消融结论

A/B/C/D + gate + soft type prior 消融说明：

```text
A anchor baseline:
  稳定基准。

B reliability only:
  当前最稳。
  Deploy Rank Corr 和 Top3 Overlap 明显提升。

C subject floor:
  下降，不推荐。

D subject floor + context cap:
  进一步下降，不推荐。

soft type prior:
  也低于 reliability only，不推荐默认使用。

update gate:
  当前 Biker/HOOT 上未过滤任何帧，暂时不能证明有效。
```

当前推荐 Stage 2 默认配置：

```bash
--language_word_reliability 1
--language_word_reliability_source target_hardneg_gap
--language_word_reliability_momentum 0.9
--language_word_reliability_tau 0.1
--language_subject_min_reliability 0
--language_context_max_weight 1
--language_subject_type_prior 1.0
--language_attribute_type_prior 1.0
--language_context_type_prior 1.0
```

## 2.4 重要认识

Stage 2 不应继续引入更多词类型规则。

保留：

```text
word_gap
word_reliability
final_word_weight
rank alignment
```

暂不使用：

```text
subject floor
context cap
soft type prior
hard word filtering
BLIP candidate
```

词分类只作为分析标签，不作为默认决策变量。

# Stage 3：Language-Conditioned Multi-Query Prior

## 3.1 为什么需要 Stage 3

Stage 2 仍然偏诊断和规则式 runtime 调权，存在几个局限：

```text
1. 固定 anchor 词集合，无法处理语言描述过时。
2. 不引入 BLIP 新语言状态。
3. 词级 reliability 改善了 rank alignment，但没有明显转化为 IoU。
4. 手工 subject/context 规则被实验证明不可靠。
5. 不够端到端，缺少可训练的语言调优模块。
```

因此 Stage 3 应转向：

```text
language-conditioned multi-query prior
```

不是继续做：

```text
BLIP caption -> 拆词 -> 手工筛选 -> 加权
```

而是：

```text
language state -> language queries -> search-token prior -> center-score bias
```

---

## 3.2 建模思想

参考 language-as-query / prompt-learning 思想：

```text
语言不是简单作为附加描述；
语言应生成一组 query，用这些 query 去 search tokens 中定位目标。
```

适合 DUTrack 的轻量形式：

```text
L_anchor / L_current / L_blip
    ↓
shared language-query generator
    ↓
K language-conditioned queries
    ↓
query-search compatibility / cross-attention
    ↓
search-space prior
    ↓
bounded center-score bias
```

目标：

```text
不改 backbone
不改 size branch
不改 offset branch
只对 center score 做有界修正
```

---

## 3.3 三个建模层级

### Level 1：Single sentence query

```text
q = Σ_i r_i W_l word_i
P(j) = q · W_v x_j
```

优点：

```text
简单、参数少。
```

缺点：

```text
会把 subject / attribute / relation / context 混成一个向量。
容易退化成加权全句 pooling。
```

结论：

```text
只适合作为 baseline，不建议作为主线。
```

---

### Level 2：Per-word queries

```text
q_i = W_l word_i
P_i(j) = q_i · W_v x_j
P_lang(j) = Σ_i r_i P_i(j)
```

优点：

```text
保留词级响应；
可视化清楚；
与 Stage 1/2 的 word_gap / reliability 兼容。
```

缺点：

```text
仍然难以建模复杂关系短语，如 head of man / man on bike / held by person。
```

结论：

```text
适合作为 Stage 3-A 的诊断基线。
```

---

### Level 3：Multi language-conditioned queries

```text
Q = QueryGenerator(language_tokens)
Q = {q_1, q_2, ..., q_K}

P_k(j) = compatibility(q_k, search_token_j)
P_final(j) = QueryFusion(P_1, ..., P_K)
```

优点：

```text
多个 query 可学习地表达目标的不同侧面；
减少手工 subject/context/attribute 规则；
更接近端到端语言调优；
可借鉴 language-as-queries 中少量 query 表示一个 referring target 的思想。
```

建议：

```text
K = 4 或 5
```

不要手工规定每个 query 的角色，让模型训练后自然分化。

---

## 3.4 Stage 3-A：非训练诊断版

目标：

```text
先验证不同语言源生成的 prior 是否真的有定位价值。
```

候选语言源：

```text
L_anchor: 初始身份语言
L_current: 当前语言状态
L_blip: 原项目 BLIP 触发后生成的 caption
L_anchor+blip: anchor 与 BLIP 拼接或融合
```

暂时不改 BLIP 触发规则，沿用原项目逻辑。

每个语言源使用同一套共享模块：

```text
shared W_l
shared W_v
shared Query/Prior Generator
```

这样不同语言源的 prior 分数才可比较。

### 3.4.1 推荐计算

对每个语言源 `L_m`：

```text
Q_m = QueryGenerator(L_m)
P_m(j) = PriorGenerator(Q_m, search_tokens)
```

计算视觉证据：

```text
gap_m = mean_{j in P_pred} P_m(j) - mean_{j in N_hard} P_m(j)
```

记录：

```text
gap_anchor
gap_current
gap_blip
gap_anchor_blip
Score GT Mass
On/Off Peak Delta
Peak distance
language drift indicators
```

### 3.4.2 诊断目标

判断：

```text
1. BLIP language 是否在部分帧比 anchor 更有定位证据？
2. anchor 是否在多数帧仍然更稳？
3. anchor+BLIP 是否优于单独 anchor 或单独 BLIP？
4. BLIP 是否经常偏向背景或上下文？
```

只有当 BLIP 在某些帧确实产生更高 target-hardneg gap 时，才值得进入语言源融合或训练。

---

## 3.5 Stage 3-B：Language Evidence Router

如果 Stage 3-A 证明不同语言源确实各有优势，则进入语言源路由。

核心思想：

```text
语言源不是直接被信任；
语言源必须通过 search token 验证；
能区分 P_pred 和 N_hard 的语言 prior 才被放大。
```

对每个语言源：

```text
P_anchor
P_blip
P_current
```

计算：

```text
gap_anchor
gap_blip
gap_current
```

融合：

```text
alpha = smooth_softmax([gap_anchor, gap_blip, gap_current] / tau_lang)

P_final = Σ_m alpha_m P_m
```

注意：

```text
alpha 不应过于 one-hot；
低置信帧不应激进切换语言源；
anchor 是 identity reference，不是永远固定的最终输入。
```

---

## 3.6 Stage 3-C：可学习端到端模块

最终目标不是手工 gap 路由，而是轻量可学习模块：

```text
Language Query Generator
Language Evidence Router
Center-score Prior Head
```

建议结构：

```text
Input:
  language tokens from anchor/current/blip
  search tokens
  base score map

Module:
  shared language-query generator
  cross-attention / compatibility with search tokens
  source router
  prior head

Output:
  bounded center-score prior
```

注入方式：

```text
score_logits_final =
score_logits_base + beta * bounded_norm(P_final)
```

不影响：

```text
size branch
offset branch
backbone attention
```

# 4. Query 模块工程设计

## 4.1 共享权重

anchor / BLIP / current 三路语言必须共享同一套模块：

```text
W_l: language projection
W_v: visual projection
QueryGenerator
PriorGenerator
```

不要为每路语言设计独立权重，否则：

```text
1. 参数量增加；
2. 分数尺度不一致；
3. gap_anchor / gap_blip 不可公平比较。
```

---

## 4.2 跨模态投影

必须保证语言 query 和视觉 token 在可比较空间中：

```text
q_language = normalize(W_l language)
k_visual   = normalize(W_v search)
sim        = q_language · k_visual
```

不能假设 raw BERT token 和 raw visual token 天然语义对齐。

当前更合理表述：

```text
在 DUTrack 已融合 token 空间中，用可学习投影后的 word-visual compatibility 作为语言-视觉证据。
```

---

## 4.3 不建议全句 pooling

避免：

```text
q = Pool(L_sentence)
```

因为它会混合：

```text
主体词
属性词
关系短语
上下文词
背景词
```

优先考虑：

```text
per-word queries
或
multi language-conditioned queries
```

---

## 4.4 是否使用 Stage 2 reliability

建议用于诊断版，但不应成为长期唯一机制。

Stage 3-A 可使用：

```text
q_i = r_i W_l word_i
```

因为 Stage 2 已证明 reliability only 能提升 rank alignment。

但端到端版应允许模型学习 query 权重：

```text
q_i weight = learned function(word token, visual evidence, history)
```

而不是长期依赖手工 EMA reliability。

# 5. Loss 设计建议

## 5.1 Score-space rank loss

对加 prior 后的 score：

```text
S_after = S_base.detach() + prior_bias
```

定义：

```text
L_score_rank = ReLU(m - mean(S_after_P) + mean(S_after_N))
```

其中：

```text
P: GT center 或高质量目标区域
N: GT 外 hard negative 区域
```

## 5.2 Prior rank loss

直接约束 prior：

```text
L_prior_rank = ReLU(m_p - mean(Prior_P) + mean(Prior_N))
```

## 5.3 Bias regularization

避免 prior 过强：

```text
L_bias = ||prior_bias||^2
```

总损失：

```text
L_aux = L_score_rank + μ L_prior_rank + λ L_bias
```

建议：

```text
aux weight 小；
前期启用，后期退火；
先冻结 backbone 和 size/offset branch；
只训练 query prior module 和必要的 center-score adapter。
```

# 8. 当前阶段的核心结论

当前实验主线应收敛为：

```text
Stage 2:
  固定词集合下，验证 word-level visual evidence 与 reliability 是否可靠。

Stage 3:
  不再手工筛词，而是让不同语言状态生成 query/prior，
  通过 visual evidence 诊断和融合语言源。

Stage 4:
  将 query/prior/router 做成可学习模块，
  用 score-space loss 和 tracking loss 端到端适配 center score。
```

最终目标不是做一个复杂的规则系统，而是形成：

```text
Language-conditioned query prior for vision-language tracking
```

它的核心特点是：

```text
1. anchor 作为 identity reference，而不是永远固定输入；
2. BLIP 作为候选语言源，而不是直接替换语言；
3. 语言通过 queries 参与视觉定位；
4. 视觉证据决定语言源是否可信；
5. 最终只对 center score 做有界修正；
6. query prior module 可以被端到端训练。
```
