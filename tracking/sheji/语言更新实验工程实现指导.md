# 语言更新实验工程实现指导

## 1. 当前目标

当前语言更新实验的目标不是让 BLIP 重新生成一句更自然的 caption，而是构建一个更稳定、更可控的语言状态更新机制。

核心原则：

```text
主体身份保持稳定
属性词和上下文词可以根据视觉证据动态调整
BLIP 只提供候选补充词，不直接替换当前语言
所有语言更新都必须有可解释的视觉证据
```

当前应避免的旧逻辑是：

```text
触发更新
→ BLIP 生成新 caption
→ 整句替换当前语言
```

这种做法容易造成目标身份漂移。例如：

```text
head of the man on the bike
→ a man riding a bike
```

目标从 `head` 被扩展成 `man / bike`，后续 word-level prior 会被错误语言源带偏。

---

## 2. 当前阶段定位

当前项目已经完成的部分：

```text
1. 支持 anchor / caption_replace / off 三种语言更新策略
2. 支持 dataset_or_class 等初始语言来源
3. 支持 language_descriptions.csv 读取数据集侧初始语言
4. 支持 BLIP lazy load
5. 支持测试时 hard word filtering 初版
6. 支持记录 language_anchor / language_source / filtered description 等诊断字段
```

当前尚未完成、也是下一阶段重点的部分：

```text
1. 明确可靠的 word reliability 计算
2. 不再只依赖 word_level_weights 做筛词
3. 用目标区域 vs hard negative 的差值作为视觉证据
4. 实现 soft word reliability，而不是直接删词改句子
5. 支持 BLIP 候选词补充，但不整句替换
6. 记录修正前后和修正依据
7. 将更新后的词权重接入 word-level prior
```

## 3. 语言状态设计

建议把语言状态拆成三类词，而不是把整句当作一个不可分割 caption。

### 3.1 Subject Words：主体词

主体词表示目标身份，原则上保持稳定。

例子：

```text
head
backpack
vehicle
dog
person
```

规则：

```text
1. 主体词来自初始 anchor
2. 主体词不轻易删除
3. 主体词不被 BLIP 新 caption 直接替换
4. 主体词即使短期视觉证据弱，也应保留较高下限
```

建议设置：

```text
subject_min_reliability = 0.7
subject_max_drop = False
```

### 3.2 Attribute Words：属性词

属性词描述目标外观，可动态调整。

例子：

```text
red
blue
dark
small
visible
occluded
```

规则：

```text
1. 属性词可以根据视觉证据升权或降权
2. BLIP 生成的新属性词可以作为候选补充
3. 新属性词必须通过视觉验证
4. 新属性词初始权重应较低
```

### 3.3 Context Words：上下文词

上下文词用于辅助定位，但不能抢占主体。

例子：

```text
man
bike
chair
person
hand
road
building
```

规则：

```text
1. 上下文词可以辅助定位
2. 上下文词不能压过主体词
3. 如果上下文词长期指向 hard negative，应降权
4. 上下文词不应作为目标主体参与强匹配
```

建议设置：

```text
context_max_weight = 0.4
```

## 4. Word Reliability 计算公式

当前 hard word filtering 主要依赖 `word_level_weights`。这只能说明某个词在模型内部被关注，不一定说明它能区分目标和干扰物。

下一阶段应改成基于目标区域和 hard negative 的视觉证据。

### 4.1 词级响应

对第 `i` 个词，在第 `t` 帧，先得到它在 search token 上的响应：

```text
R_i^t(j)
```

其中：

```text
i = word index
j = search token index
t = frame index
```

### 4.2 目标区域响应

定义目标区域 token 集合：

```text
P_t
```

推荐来源：

```text
1. 当前预测框中心附近 token
2. 当前预测框内部 token
3. base score 高置信目标区域
```

然后计算：

```text
s_i^pos(t) = mean_{j in P_t} R_i^t(j)
```

### 4.3 Hard Negative 区域响应

定义 hard negative token 集合：

```text
N_t
```

推荐来源：

```text
1. 当前预测框外部
2. base score 较高的 top-k tokens
3. 与目标区域有足够空间距离
```

然后计算：

```text
s_i^neg(t) = mean_{j in N_t} R_i^t(j)
```

### 4.4 当前帧视觉证据

```text
e_i(t) = s_i^pos(t) - s_i^neg(t)
```

含义：

```text
e_i(t) > 0:
  该词更支持目标区域

e_i(t) ≈ 0:
  该词区分能力弱

e_i(t) < 0:
  该词更可能指向 hard negative 或背景
```

### 4.5 归一化证据

```text
v_i(t) = sigmoid(e_i(t) / tau)
```

建议初始参数：

```text
tau = 0.05 或 0.1
```

含义：

```text
v_i(t) 接近 1:
  当前帧强支持该词

v_i(t) 接近 0.5:
  当前帧证据不明显

v_i(t) 接近 0:
  当前帧该词可能误导
```

### 4.6 历史平滑

使用 EMA 更新词可靠性：

```text
r_i(t) = momentum * r_i(t-1) + (1 - momentum) * v_i(t)
```

建议初始参数：

```text
momentum = 0.8 或 0.9
```

### 4.7 最终词权重

```text
w_i(t) = w_i^base * r_i(t) * type_gate_i
```

其中：

```text
w_i^base:
  初始语言解析得到的基础权重

r_i(t):
  视觉证据更新后的可靠性

type_gate_i:
  词类型约束，例如 subject / attribute / context
```

推荐约束：

```text
subject:
  r_i(t) = max(r_i(t), subject_min_reliability)

attribute:
  正常使用 r_i(t)

context:
  w_i(t) = min(w_i(t), context_max_weight)
```

## 5. BLIP 使用方式

### 5.1 不推荐的方式

不建议继续使用：

```text
BLIP caption
→ 整句替换当前语言
```

原因：

```text
1. 容易改变目标身份
2. 容易生成整图显著物体
3. 对局部目标不友好
4. 会让 word-level prior 被错误语义带偏
```

### 5.2 推荐的方式

BLIP 只作为候选词来源：

```text
当前目标 crop / search crop
→ BLIP caption
→ 分词
→ 候选词分类
→ 视觉验证
→ 低权重加入动态词表
```

### 5.3 可尝试的 BLIP Prompt

可以尝试让 BLIP 生成更适合 tracking 的短语：

```text
Describe the visible target object using short phrases. Focus on the target identity, visible attributes, and nearby context. Do not describe the whole image.
```

或者：

```text
Describe the target object with short phrases: target object, visible attributes, and nearby context. If a part is unclear, omit it.
```

如果模型支持更强 prompt-following，可以尝试：

```text
Output short phrases in this form if possible:
target: ...
attributes: ...
context: ...
```

注意：

```text
blip-image-captioning-base 不一定稳定遵守结构化格式。
所以 prompt 只能作为软约束，后处理和视觉验证仍然必须保留。
```

## 6. BLIP 候选词筛选机制

### 6.1 候选词提取

从 BLIP caption 中提取候选词，并分类为：

```text
subject candidate
attribute candidate
context candidate
background candidate
```

建议初版只允许：

```text
attribute candidate
context candidate
```

暂时不要让 BLIP 新增 subject，避免身份漂移。

### 6.2 候选词视觉证据

对候选词 `c`：

```text
e_c(t) = s_c^pos(t) - s_c^neg(t)
v_c(t) = sigmoid(e_c(t) / tau)
```

### 6.3 加入条件

建议要求连续多帧通过验证：

```text
v_c(t) > add_threshold for K frames
```

推荐参数：

```text
add_threshold = 0.65
K = 2 或 3
```

### 6.4 初始权重

通过验证后低权重加入：

```text
w_c(t) = alpha_new * v_c(t)
```

推荐：

```text
alpha_new = 0.2 或 0.3
```

### 6.5 移除或降权规则

对非主体词：

```text
如果连续 K_drop 帧 evidence 低:
  降权

如果长期 e_i(t) < 0:
  暂停使用
```

推荐：

```text
K_drop = 3 或 5
```

主体词不执行硬删除。

## 7. 语言更新触发策略

不建议每帧都调用 BLIP。建议只在需要时触发。

触发条件可以包括：

```text
1. base score 置信度下降
2. center score peak 变平
3. hard negative 与目标分数接近
4. 遮挡或目标外观变化明显
5. 当前 word reliability 整体下降
```

示例：

```text
if max_score < score_threshold:
    trigger_blip = True

if score_gap_base < gap_threshold:
    trigger_blip = True

if mean_word_reliability < rel_threshold:
    trigger_blip = True
```

触发后仍然不整句替换，只进行候选词补充。

## 8. 诊断与日志设计

该模块必须可解释。每次语言更新或词权重变化，都应记录修正依据。

### 8.1 每帧记录

建议 CSV 字段：

```text
frame_id
language_anchor
active_words
blip_caption
candidate_words
word_reliability
word_final_weights
word_pos_score
word_hardneg_score
word_gap
added_words
suppressed_words
language_update_reason
score_gap_before
score_gap_after
peak_distance_before
peak_distance_after
```

### 8.2 每个词记录

每个词建议记录：

```text
word
word_type
base_weight
s_pos
s_hardneg
gap
visual_evidence
reliability_before
reliability_after
final_weight
decision
reason
```

其中 `decision` 可以是：

```text
keep
downweight
suppress
add_candidate
ignore_candidate
```

### 8.3 可视化

建议保存：

```text
1. 每个词的 reliability 曲线
2. 每个词的 search response heatmap
3. 当前 active word list
4. BLIP candidate word list
5. score map before / after prior
6. hard negative token 可视化
```

## 9. 消融实验设计

### 9.1 BLIP Prompt 消融

至少对比：

```text
A. no BLIP
B. BLIP caption_replace
C. BLIP prompt only
D. BLIP candidate + visual verification
```

观察指标：

```text
IoU
language changes
unique language count
word_gap
word_hardneg_gap
score GT mass
score top10
on/off peak delta
identity drift cases
```

### 9.2 Reliability 消融

至少对比：

```text
A. no reliability
B. word_level_weights EMA
C. target-hardneg gap EMA
D. target-hardneg gap EMA + type constraints
```

重点判断：

```text
1. reliability 是否稳定
2. 是否减少语言抖动
3. 是否提升 target vs hard negative gap
4. 是否改善 score peak
```

### 9.3 硬筛词 vs 软权重

至少对比：

```text
A. hard filtering description
B. soft word reliability weights
C. soft weights + optional candidate words
```

预期：

```text
soft weights 应该比 hard filtering 更稳定。
```

## 10. 推荐实现阶段

### Stage 1：只做诊断，不改变语言

目标：

```text
验证词级视觉证据是否可信。
```

实现：

```text
计算 word_pos_score / word_hardneg_score / word_gap
保存 reliability 曲线和 heatmap
不改变输入语言
```

### Stage 2：Soft Word Reliability

目标：

```text
保留 anchor 原句，动态调整内部词权重。
```

实现：

```text
anchor text 不变
更新 r_i(t)
final_word_weight_i = base_weight_i * r_i(t) * type_gate_i
接入 word-level prior
```

### Stage 3：BLIP Candidate Supplement

目标：

```text
利用 BLIP 生成的有用新词，但避免整句漂移。
```

实现：

```text
BLIP caption -> candidate words
candidate words 通过视觉验证
低权重加入 dynamic word pool
```

### Stage 4：结构化短语输出

目标：

```text
方便解释和可视化。
```

实现：

```text
subject + reliable attributes + reliable context
```

注意：

```text
结构化短语主要用于日志和可视化，不一定要作为模型唯一输入。
模型内部优先使用 soft word weights。
```

## 12. 总结

最终语言更新策略应是：

```text
主体词保持稳定；
属性词和上下文词根据视觉证据动态调整；
BLIP 只提供候选词，不直接替换原语言；
候选词必须通过 target vs hard negative 的视觉验证；
更新过程必须记录修正前后和修正依据。
```

一句话概括：

```text
不要让 BLIP 决定语言更新，而要让视觉证据决定哪些词可靠。
```
